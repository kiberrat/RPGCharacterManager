# RPG Character Manager

Универсальная настольная платформа для ролевых игр: создание персонажей, игровых систем,
механик и контента без изменения исходного кода приложения.

Техническое задание лежит рядом с решением, в каталоге `Dndapp`: главный промпт,
`ROADMAP.md` и `STYLE_GUIDE.md` — в его корне, описания подсистем — в `Dndapp/docs`.

---

## Запуск приложения

Готовое приложение находится здесь:

```
publish\RPGCharacterManager.exe
```

Запускайте двойным щелчком. **Устанавливать .NET не нужно**: среда выполнения включена
внутрь файла. Приложение можно скопировать на другой компьютер с Windows 10 или 11 —
достаточно самого файла.

При первом запуске Windows может показать предупреждение SmartScreen, поскольку файл
не подписан цифровым сертификатом. Нажмите «Подробнее» → «Выполнить в любом случае».

Пересобрать этот файл после изменений в коде:

```powershell
.\build.ps1 Publish
```

## Требования для разработки

- Windows 10 или Windows 11
- .NET 8 SDK — только для сборки из исходного кода

На этой машине SDK установлен в профиль пользователя:
`%LOCALAPPDATA%\Microsoft\dotnet`. Он **не добавлен в PATH**, а системный каталог
`C:\Program Files\dotnet` содержит только среду выполнения .NET 6. Поэтому обычная
сборка (`build.ps1 Build`) создаёт приложение, которому требуется переменная
`DOTNET_ROOT`, — скрипт задаёт её самостоятельно.

Именно поэтому для повседневного запуска используется автономная сборка из каталога
`publish`: она не зависит ни от переменных окружения, ни от установленного .NET.

## Структура решения

```
src/
    RPGCharacterManager.Shared          примитивы без зависимостей
    RPGCharacterManager.Core            модели, контракты, события
    RPGCharacterManager.Infrastructure  журналирование, настройки, шина событий
    RPGCharacterManager.Database        SQLite и Entity Framework Core
    RPGCharacterManager.Engine          единый движок вычисления формул
    RPGCharacterManager.GameRules       игровые правила: события, условия, действия
    RPGCharacterManager.Content         виды игрового контента и их редактирование
    RPGCharacterManager.Characters      мастер создания персонажа и пересчёт параметров
    RPGCharacterManager.Items           оружие, экипировка и инвентарь персонажа
    RPGCharacterManager.Dice            броски кубиков, история и любимые броски
    RPGCharacterManager.History         журнал событий: что происходило и когда
    RPGCharacterManager.Campaigns       кампании: состав игры и её хронология
    RPGCharacterManager.Master          режим мастера: сводка, массовые действия, очередь хода
    RPGCharacterManager.Layouts         макеты интерфейса: вкладки, панели, размеры
    RPGCharacterManager.Search          глобальный поиск по всем подсистемам
    RPGCharacterManager.Macros          макросы: действия, условия, горячие клавиши
    RPGCharacterManager.Statistics      статистика бросков, критов, урона и расходов
    RPGCharacterManager.Extensions      расширения: установка, обновление, выгрузка
    RPGCharacterManager.Import          чтение документов: PDF, DOCX, HTML, JSON, SQLite
    RPGCharacterManager.Ai              помощник: чат, разбор книг, проверка базы
    RPGCharacterManager.UI              представления и модели представления
    RPGCharacterManager.App             точка входа и корень композиции
tests/
    RPGCharacterManager.Tests           автоматические тесты
docs/
    ARCHITECTURE_DECISIONS.md           принятые архитектурные решения
```

Направление зависимостей:

```
Shared → Core → Infrastructure  ┐
                Core → Database  ┤
                Core → Engine    ┤
                Core → GameRules ┤
                Core → Content   ┼→ App
                Core → Characters┤
                Core → Items     ┤
                Core → Dice      ┤
                Core → History   ┤
                Core → Campaigns ┤
                Core → Master    ┤
                Core → Layouts   ┤
                Core → Search    ┤
                Core → Macros    ┤
                Core → Statistics┤
                Core → Extensions┤
                Core → Import    ┤
                Core → Ai        ┤
                Core → UI        ┘
```

Исключение: `Content`, `Characters`, `Items`, `Dice`, `History`, `Campaigns`,
`Master`, `Layouts`, `Macros`, `Statistics` и `Extensions` дополнительно
ссылаются на `Database`, поскольку работают с игровыми объектами произвольного
вида и обращаются к контексту напрямую. `Macros` ссылается ещё и на `GameRules`:
макрос хранит те же условия и действия, что и правило.

`Ai` и `Search` этого исключения не требуют: помощник читает и изменяет игровые
объекты только через службу контента, а поиск получает находки от служб самих
подсистем, — поэтому о базе данных они не знают вовсе.

`UI` использует только контракты из `Core` и не знает о реализациях. Конкретные
реализации известны единственному проекту — `App`.

## Данные пользователя

Все пользовательские данные хранятся отдельно от файлов приложения, в каталоге
`%APPDATA%\RPGCharacterManager`:

| Расположение     | Назначение                          |
|------------------|-------------------------------------|
| `rpgmanager.db`  | база данных SQLite                  |
| `settings.json`  | пользовательские настройки          |
| `logs\`          | журналы работы приложения           |
| `backups\`       | резервные копии базы данных         |
| `content\`       | изображения и книги                  |
| `content\books\` | книги для разбора помощником        |

Удаление приложения не затрагивает эти данные.

## Помощник

Раздел «AI» обращается к службе языковых моделей и потому требует подключения
к сети. Всё остальное приложение работает без неё.

Поддерживаются три службы, выбор — в «Настройки» → «Помощник»:

| Служба           | Ключ выдаётся на           | Особенности                                        |
|------------------|----------------------------|----------------------------------------------------|
| Groq             | `console.groq.com`         | быстрые модели, бесплатный предел обращений        |
| OpenRouter       | `openrouter.ai/keys`       | приложение показывает **только бесплатные** модели |
| Google AI Studio | `aistudio.google.com/apikey`| модели Gemini                                      |

Ключ и выбранная модель хранятся отдельно для каждой службы, поэтому переключение
туда и обратно не требует повторного ввода. Ключ сохраняется в вашем файле настроек
и передаётся только самой службе. Кнопка «Проверить связь» выполняет настоящий
запрос и показывает, какая модель ответила и за сколько времени.

Бесплатные пределы считаются для каждой модели отдельно: если служба ответила
отказом, выберите в списке другую модель — это быстрее, чем ждать.

В списке остаются только модели, умеющие вызывать инструменты. Модель без этой
возможности способна лишь рассказывать: она охотно опишет созданный объект,
которого на деле не создавала. Под каждым ответом помощника перечислено, какие
инструменты он вызвал; строка «инструменты не вызывались» означает, что в базе
ничего не появилось, что бы ни было написано в самом ответе.

Помощник ничего не меняет сам: всё, что он предлагает создать или изменить,
попадает в правый столбец раздела и применяется только вашим нажатием.

## Импорт документов

Раздел «AI» превращает внешние документы в игровые объекты. Поддерживаются:

| Формат   | Расширения                      | Что читается                                  |
|----------|---------------------------------|-----------------------------------------------|
| PDF      | `.pdf`                          | текст страниц; сканы без текста не распознаются |
| DOCX     | `.docx`                         | абзацы и таблицы                              |
| HTML     | `.html`, `.htm`, `.xhtml`       | видимый текст без скриптов и оформления       |
| Markdown | `.md`, `.markdown`              | текст вместе с разметкой                      |
| Текст    | `.txt`, `.text`                 | UTF-8 и Windows-1251                          |
| JSON     | `.json`                         | записи перечнем «поле: значение»              |
| SQLite   | `.db`, `.sqlite`, `.sqlite3`    | строки всех таблиц, только чтение             |

Файл выбирается кнопкой «Выбрать файл…» в любом месте на диске либо кладётся
в каталог `content\books` — тогда он появляется в списке сам.

Перед разбором показывается, что найдено в документе: формат, число страниц,
таблиц или записей, объём текста и на сколько частей он разобьётся. Каждая
часть — отдельное обращение к службе, поэтому цену разбора видно заранее.

Найденные объекты помощник предлагает создать: они попадают в правый столбец
и применяются нажатием, как и все остальные его предложения.

## Кампании

Раздел «Кампании» ведёт игру: её состав и хронологию.

Кампания не хранит игровые объекты, а ссылается на них. В состав входят
персонажи игроков, NPC, монстры, квесты, локации — и любой другой вид контента,
вплоть до предметов и правил, как того требует документ 026. Один и тот же
торговец или город участвует в нескольких играх, оставаясь единственной записью
в базе: удаление кампании не трогает ни одного объекта.

| Вкладка     | Что содержит                                                        |
|-------------|---------------------------------------------------------------------|
| «Кампания»  | название, мир, дата начала, игровая система, описание, заметки мастера |
| «Состав»    | участники по видам; у каждого — роль в игре и заметки                |
| «Таймлайн»  | события игрового мира в заданном вами порядке                        |

У персонажа роль называется «Игрок» — это тот, кто им играет; у остальных
участников «Роль» означает их место в игре: квестодатель, босс главы, убежище
партии.

Даты игрового мира записываются как есть: «15 день месяца Пепла, 1250 год» —
такая же дата, как обычная. Сравнивать их приложение не берётся, поэтому порядок
событий задаёте вы кнопками «Выше» и «Ниже». Раздел «Журнал» ведёт настоящее
время и с хронологией кампании не смешивается.

Объект, удалённый из приложения, остаётся в составе строкой «Объект удалён»:
ссылка показывается явно, чтобы её можно было убрать осознанно.

Сами NPC, квесты и локации создаются и правятся в разделе «Контент» — там же,
где расы, заклинания и монстры. Помощник в разделе «AI» умеет создавать их
с первого дня по той же причине: он работает с описаниями видов контента,
а не со списком, заданным в коде.

## Режим мастера

Раздел «Мастер» ведёт саму игровую сессию: показывает всех персонажей сразу
и меняет их одним действием.

Персонажи показываются списком с ресурсами и действующими эффектами; отбор
по кампании оставляет только её участников. Отмеченные галочкой персонажи —
те, на кого подействует следующее нажатие.

| Вкладка      | Что делает                                                        |
|--------------|-------------------------------------------------------------------|
| «Ресурсы»    | отнять или прибавить величину выбранного ресурса всем отмеченным    |
| «Эффекты»    | наложить или снять эффект на всех отмеченных                       |
| «Инициатива» | бросить инициативу, вести очередь хода и считать раунды            |
| «Журнал»     | общий журнал показанных персонажей                                  |

Урона как отдельного действия нет: здоровье в этом приложении — обычный ресурс,
поэтому «Отнять 7» из списка «Здоровье» наносит урон, а из списка «Мана» —
тратит ману. Значение не опускается ниже нуля и не поднимается выше максимума,
вычисленного формулой игровой системы (решение Р-91).

Очередь хода появляется, только если в игровой системе заполнена формула
инициативы, например `1к20 + Ловкость`. Пустая формула означает, что порядка
хода в этой игре нет, — и вкладка честно об этом говорит вместо того, чтобы
навязывать бой по раундам (решение Р-92). Больший результат ходит раньше;
значение можно исправить вручную прямо в строке персонажа. Очередь принадлежит
кампании и переживает закрытие приложения.

## Поиск

Раздел «Поиск» ищет сразу везде: персонажей, кампании, записи журнала и игровой
контент всех видов — заклинания, предметы, черты, монстры и остальные. Находки
показываются группами, нажатие на находку открывает нужный раздел.

Виды контента поиск не перечисляет: он берёт их из того же каталога, что
и раздел «Контент». Поэтому вид, который вы создали сами, ищется наравне
со встроенными (решение Р-96).

**Регистр не важен, в том числе у кириллицы.** Запрос «облачение» находит
«Облачение огня», а «ВОЛК» — «волколака». Встроенное в SQLite сравнение сводит
регистр только у латиницы, поэтому приложение заменяет его своим (решение Р-95).
Это касается не только раздела «Поиск»: так же теперь отбираются списки
в контенте, персонажах, журнале, заклинаниях и составе кампании.

## Макросы

Раздел «Макросы» собирает последовательности действий, которые запускаете вы:
«Второе дыхание» — восстановить здоровье и списать использование; «Ярость» —
поднять силу и наложить эффект.

**Макрос — это правило, которое запускаете вы** (решение Р-97). Условия
и действия у него те же, что у игровых правил, и редактор тот же: обработчик
действия, добавленный подсистемой, доступен и правилам, и макросам. Разница
одна: правило запускает событие, а макрос — нажатие.

| Пункт этапа              | Как сделано                                              |
|--------------------------|----------------------------------------------------------|
| последовательности       | действия выполняются сверху вниз, порядок меняется кнопками |
| пользовательские условия | то же дерево И/ИЛИ/НЕ, что в конструкторе правил          |
| формулы                  | в обеих частях сравнения и в параметрах действий           |
| горячие клавиши          | сочетание вроде `Ctrl+1` в карточке макроса               |

Горячая клавиша выполняет макрос над персонажем открытого листа (решение Р-98).
Если открыт другой раздел, нажатие объясняет, что нужен лист. Одно сочетание
принадлежит одному макросу; непонятное сочетание просто не работает
и не мешает остальным.

Макрос можно закрепить за персонажем — тогда он выполняется только над ним.

## Расширения

Раздел «Расширения» ставит и снимает наборы игровых объектов и собирает такие
наборы из того, что вы уже сделали. Плагин, контент-пак и игровая система —
это один и тот же файл `.rpgpack`, различающийся только содержимым.

**Расширение — это данные, а не программа** (решение Р-102). Внутри файла —
объекты самого приложения: игровая система с её формулами, контент любого вида,
игровые правила и макросы. Кода в расширении нет, и приложение никакого кода
не загружает. Отсюда главное свойство: расширение не может сделать ничего, чего
не можете вы сами в этом приложении, — и переживает обновление программы,
потому что читаются данные, а не двоичный код.

Отказ от библиотек ничего не отнимает: всё, ради чего плагины задуманы, здесь
и так выражается данными. Своя игровая система, свои расы, своя система критов,
своя механика брони — это записи в базе, потому что механику считает единый
движок формул, а события описывает единый конструктор правил.

| Пункт этапа                    | Как сделано                                                          |
|--------------------------------|----------------------------------------------------------------------|
| плагины                        | установка, обновление поверх старой версии, включение, отключение, удаление |
| Content Pack                   | формат `.rpgpack`: описание и содержимое в обычном zip-архиве         |
| пользовательские игровые системы | выгрузка системы вместе со всем её содержимым, правилами и макросами |
| расширения                     | состав задан перечнем видов контента, а не списком в коде             |

Перед установкой приложение проверяет версию формата, требуемую версию
приложения, зависимости от других расширений и столкновения внутренних имён,
и показывает, что именно окажется в базе. Неудавшаяся установка откатывается
целиком: наполовину установленное расширение хуже неустановленного.

Удаление убирает ровно объекты расширения — ваши собственные остаются на месте.
Игровая система при удалении сохраняется: на неё могут ссылаться персонажи,
созданные, пока расширение было установлено.

Новый вид контента попадает в расширения сам (решение Р-103): перечень видов
берётся у службы контента, а объекты записываются так, как устроены в модели
данных. Второго описания тех же полей нет — значит, нечему разойтись.

Формат открыт: файл распаковывается любым архиватором, внутри два документа
на русском — `манифест.json` и `содержимое.json`.

## Статистика

Раздел «Статистика» отвечает на вопросы, которые за столом задают чаще всего:
сколько раз бросали, везёт ли с костями, чем бьют, что применяют и на что
тратят. Отбор — по персонажу и по периоду: за всё время, за 30 дней, за 7 дней
или за сутки.

**Статистика ничего не накапливает — она считает журнал** (решение Р-99).
Собственных счётчиков у неё нет, поэтому разойтись с журналом она не может,
а очистка журнала обнуляет и её. Новое событие попадает в статистику тем же
путём, что и в журнал: подсистема записывает его у себя, и больше ничего
делать не нужно.

| Пункт этапа           | Как сделано                                                       |
|-----------------------|-------------------------------------------------------------------|
| статистика бросков    | всего, среднее, лучший и худший итог, преимущество и помеха        |
| статистика критов     | критов и их доля — всего и по каждому оружию                       |
| статистика урона      | суммарный, средний и лучший удар — всего и по каждому оружию       |
| использование заклинаний | сколько раз применено каждое заклинание                        |
| использование ресурсов | сколько израсходовано, сколько восстановлено и что вышло в итоге  |

**Крит — это то, что признало критом оружие** (решение Р-100): порог задаёте вы,
и приложение правил игры не знает. Максимум на кости считается отдельно, рядом
с ожидаемым средним, потому что это свойство кубика, а не правило игры: кость
на 777 граней учитывается так же, как d20.

Чтобы это было возможно, запись журнала хранит название объекта события
и его величину числом (решение Р-101). Иначе одно и то же заклинание,
применённое на разных уровнях, попало бы в сводку двумя строками.

## Редактор интерфейса

Раздел «Интерфейс» задаёт, из чего состоит лист персонажа. Встроенной разметки
листа больше нет: вкладки и стоящие на них панели берутся из макета.

Панель — готовая часть листа: «Параметры», «Навыки», «Оружие», «Инвентарь»
и остальные девять. Панели перетаскиваются мышью — и внутри вкладки, и на
соседнюю, поэтому расположение задаётся тем же движением, каким его задумали.

| Что можно                | Как                                                    |
|--------------------------|--------------------------------------------------------|
| несколько макетов        | «Новый макет» создаёт копию выбранного; «Применить» переключает |
| пользовательские вкладки | «Добавить вкладку» с любым заголовком                   |
| расположение             | перетаскивание панели на нужную вкладку и место         |
| размеры                  | кнопки «−» и «+» меняют долю ширины панели              |

Размер задан долей, а не пикселями: две панели с долями 1 и 2 занимают треть
и две трети вкладки на любом экране (решение Р-94). Несколько панелей на одной
вкладке встают рядом и делят её ширину.

При первом запуске приложение создаёт макет «Обычный лист» — вкладка на каждую
панель, то есть в точности привычный вид. Переделывать его необязательно:
обновление приложения ничего не переставляет.

Панель, исчезнувшая из приложения, показывается на листе предупреждением,
а не пропадает молча (решение Р-93).
