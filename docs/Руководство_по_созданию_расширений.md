# Руководство: как самостоятельно сделать расширение (книгу правил) для RPG Character Manager

Это практическое руководство для человека, а не для программиста. Всё, что
здесь описано, делается **внутри самого приложения**, мышью и клавиатурой —
никакого кода, JSON или сборки писать не нужно. Именно так устроена и
установленная у вас «Книга игрока D&D 5e»: она была собрана из тех же самых
полей, которые видны в разделе «Контент».

---

## 1. Как это устроено (коротко)

Три уровня вложенности:

1. **Игровая система** («Dungeons & Dragons 5-е издание», «Pathfinder 2e»,
   «Ваш киберпанк» — что угодно). Задаёт правила по умолчанию: единицу веса,
   формулу переносимого груза, формулу пределов заклинаний и т. д.
2. **Объекты контента**, привязанные к системе: расы, классы, заклинания,
   предметы, оружие, эффекты и так далее. Каждый объект отмечен, какой
   игровой системе он принадлежит.
3. **Файл расширения (`.rpgpack`)** — это просто выгрузка: все объекты одной
   игровой системы, упакованные в zip-архив с описанием (манифестом). Файл
   можно переслать кому угодно, и он установится в раздел «Расширения» одной
   кнопкой.

Важно понимать одну вещь, из-за которой у вас изначально ничего не появлялось
в мастере создания персонажа: **список рас/классов в мастере фильтруется по
выбранной игровой системе.** Если объект не привязан ни к одной системе — он
виден всегда. Если привязан — виден только когда выбрана именно эта система.
Поэтому **у каждого объекта, который вы создаёте для своей книги, обязательно
должно быть заполнено поле «Игровая система».** Это единственное правило,
которое действительно нельзя нарушать — всё остальное чуть более гибкое.

(Отдельно от игровой системы есть ещё «Контент-пак» — но это поле не
показывается в общей форме редактирования и заполняется автоматически, когда
вы устанавливаете чужое расширение. Создавая контент сами, вы про него можете
забыть.)

---

## 2. Общий порядок работы

1. **Контент → Игровые системы → Создать.** Одна запись — один сеттинг/одна
   книга правил.
2. Наполняете систему контентом (см. рекомендуемый порядок ниже — он важен
   только потому, что некоторые поля — это выпадающие списки, ссылающиеся на
   уже существующие объекты; если нужного объекта ещё нет, ссылку поставить
   не на что).
3. **У каждого создаваемого объекта в поле «Игровая система» выбираете вашу
   систему из шага 1.** Без этого шага объект не попадёт в расширение и не
   будет виден в мастере персонажа.
4. **Расширения → Выгрузить.** Источником выбираете вашу игровую систему,
   заполняете название/версию/автора/описание — получаете готовый `.rpgpack`.
5. Проверяете: создаёте тестового персонажа в мастере — раса/класс должны
   появиться в списках. Если система только одна установленная — она
   выберется автоматически на первом шаге мастера.

### Рекомендуемый порядок наполнения (из-за ссылок между объектами)

Порядок важен только там, где один объект ссылается на другой через
выпадающий список:

1. **Характеристики** (Сила, Ловкость и т. п.) — на них ссылается почти всё
   остальное.
2. **Навыки** — ссылаются на характеристики.
3. **Ресурсы** (Здоровье, Мана и т. п.) — на них ссылаются заклинания,
   способности, предметы, отдых.
4. **Слоты экипировки** (Голова, Тело, Основная рука...) — на них ссылаются
   предметы и оружие.
5. **Категории предметов** (если нужны).
6. **Расы, Происхождения** — обычно ни на что не ссылаются, порядок неважен.
7. **Классы**, затем **Подклассы** (подкласс ссылается на класс).
8. **Черты**, **Способности**.
9. **Заклинания**.
10. **Предметы**, затем **Оружие** (оружие — это предмет с доп. свойствами,
    ссылается на характеристику масштабирования и навык владения).
11. **Эффекты** (состояния вроде «Отравлен», «Оглушён»).
12. **Виды отдыха**.

Если вы всё же создали что-то не в этом порядке — ничего страшного, просто
вернитесь и заполните пропущенную ссылку потом; ничего не потеряется.

## 3. Справочник полей по каждому виду контента

Общие поля есть у всех объектов контента (кроме самой «Игровой системы» и
«Контент-пака», у них набор немного другой):

| Поле | Что писать |
|---|---|
| **Название** | То, что видит игрок. «Эльф», «Огненный шар». |
| **Внутреннее имя** | Заполняется автоматически по названию, латиницей/кириллицей без пробелов — по нему объект узнают формулы (`сила`, `ловкость` и т. п.). Обычно трогать не нужно, но если два объекта получат одинаковое внутреннее имя — переименуйте одно вручную. |
| **Описание** | Полный текст из книги — то, что игрок прочитает в приложении. |
| **Источник** | «Книга игрока, с. 45» — просто для справки, ни на что не влияет. |
| **Игровая система** | **Обязательно** ваша система (см. раздел 1). |
| **Изображение / Значок** | Необязательно. |

Дальше — то, что специфично для каждого вида.

### Игровая система

| Поле | Что писать |
|---|---|
| Название, Внутреннее имя, Версия, Автор, Описание | Как обычно. |
| Система включена | Да. |
| Единица веса | «кг», «фунтов», «ячеек» — как в вашей книге. |
| Формула переносимого веса | Например `Сила * 10`. Пусто — ноша не ограничена. |
| Формула предела известных заклинаний | Например `Интеллект + Уровень`. Пусто — не ограничено. |
| Формула предела подготовленных заклинаний | Заполнено — заклинания нужно готовить явно (как жрец/друид/волшебник D&D). Пусто — эта механика не используется. |

### Характеристики (Сила, Ловкость, Мудрость...)

| Поле | Что писать |
|---|---|
| Значение по умолчанию | Обычно 10. |
| Минимум / Максимум | Например 1 и 20 (или 30 для существ). Пусто — без ограничений. |
| Скрытая характеристика | Включите для служебных величин вроде «Бонус мастерства» — игрок её не редактирует и не видит в общем списке, но формулы могут её использовать. |
| Формула значения | Заполняется, ТОЛЬКО если характеристика вычисляемая (не редактируется игроком напрямую), например «Бонус мастерства» = `2 + ОкруглитьВниз((Уровень - 1) / 4)`. |
| Формула модификатора | Для обычных характеристик D&D-типа: `ОкруглитьВниз((Значение - 10) / 2)`. Внутри этой формулы своё же значение доступно как `значение`. |

### Навыки

| Поле | Что писать |
|---|---|
| Связанная характеристика | Какая характеристика лежит в основе (Атлетика → Сила). |
| Максимальный уровень владения | Обычно 1 (владеешь / не владеешь). Если в системе есть «экспертность» — 2. |
| Формула значения | Например `характеристика + владение * бонус_мастерства` — здесь `владение` это уровень владения (0/1/2), `бонус_мастерства` — внутреннее имя скрытой характеристики бонуса мастерства, `характеристика` — модификатор связанной характеристики. |
| Требования | Обычно пусто. |

Совет: если у вас в системе есть владение оружием (простое/воинское), их
удобно тоже сделать «Навыками» с максимальным уровнем 1 — именно так
устроено в поставленной D&D 5e (два псевдонавыка «Простое оружие» и «Воинское
оружие»), и оружие потом ссылается на такой навык как «Навык владения».

### Расы

| Поле | Что писать |
|---|---|
| Скорость | Число, например 30 (футов) или 9 (метров). |
| Размер | «Маленький», «Средний», «Большой» — как в книге. |
| Языки | Через запятую: «Общий, Эльфийский». |
| Требования | Обычно пусто. Пример при необходимости: `сила >= 15`. |
| Описание | Весь текст расы из книги — не сокращайте, это единственное место, где игрок его прочитает. |

### Происхождения (предыстории)

Те же общие поля + «Требования». Специфичных полей нет — весь текст
(владения, снаряжение, черта происхождения) идёт в «Описание».

### Классы

| Поле | Что писать |
|---|---|
| Роль | Свободный текст: «боец», «заклинатель», «плут-разведчик». |
| Основная характеристика | Ссылка на характеристику (Сила для Воина, Интеллект для Волшебника). |
| Начальный / Максимальный уровень | Обычно 1 и 20. |
| Формула здоровья за уровень | Например `1к10 + телосложение` (или `1d10 + телосложение` — «к» и «d» равнозначны). |
| Требования | Обычно пусто. |

### Подклассы

| Поле | Что писать |
|---|---|
| Класс | Ссылка на родительский класс — **обязательно**. |
| Доступен с уровня | На каком уровне выбирается (обычно 1–3). |
| Требования | Обычно пусто. |

### Черты (feats/taланты)

| Поле | Что писать |
|---|---|
| Категория | Свободный текст: «раса», «класс», «общая черта» и т. п. |
| Уровень или ранг черты | Для черт с несколькими ступенями; иначе 0. |
| Требуемая черта | Ссылка, если черта требует другую как пререквизит. |
| Формула эффекта | Если черта что-то вычисляет. |
| Формула количества использований | Пусто — черта пассивная. |
| Условие действия | Пусто — работает всегда. |
| Требования | Например `уровень >= 4`. |

### Способности (активные умения)

Похоже на черты, но с расходом ресурса: «Ресурс», «Формула стоимости»
(сколько тратится), «Формула результата», «Восстановление».

### Заклинания

| Поле | Что писать |
|---|---|
| Уровень | 0 для заговора, 1–9 для заклинаний. |
| Школа | «Воплощение», «Некромантия» и т. п. |
| Время накладывания | «1 действие», «1 бонусное действие», «1 реакция». |
| Дальность | «60 футов», «Касание», «На себя». |
| Область действия | «20-футовая сфера» и т. п., если применимо. |
| Компоненты | «В, С, М (щепотка серы)». |
| Длительность | «Мгновенная», «Концентрация, вплоть до 1 минуты». |
| Требует концентрации | Да/нет — влияет на игровую механику (можно держать только одно заклинание с концентрацией). |
| Можно применить как ритуал | Да/нет. |
| Расходуемый ресурс | Обычно пусто (ячейки заклинаний считаются отдельно движком книги заклинаний); заполняйте, только если заклинание тратит именно игровой ресурс (мана, очки маны и т. п.). |
| Формула результата | Например `8к6` (урон) или `2к8 + интеллект` (лечение). Оставляйте пустым для чисто описательных заклинаний без числового эффекта. |
| Формула усиления | На сколько усиливается при использовании ячейки более высокого уровня, например `1к6` (добавляется за каждый уровень ячейки сверху). |
| Требования | Обычно пусто. |

### Ресурсы (Здоровье, Мана, Ярость...)

| Поле | Что писать |
|---|---|
| Формула максимума | Например `10 + Уровень * 5` для здоровья или `Интеллект * 8` для маны. |
| Формула начального значения | Пусто — по умолчанию равно максимуму. |
| Правило восстановления | Свободный текст-подсказка: «после длительного отдыха» — это описание для игрока; фактическое восстановление настраивается в «Видах отдыха». |
| Цвет полосы | Для интерфейса, необязательно. |

### Эффекты (состояния/баффы/дебаффы)

Ими же описываются условия D&D — «Отравлен», «Оглушён», «Испуган» и т. д.

| Поле | Что писать |
|---|---|
| Категория | Свободный текст: «состояние», «болезнь», «благословение». |
| Окраска | «Положительная» / «Отрицательная» / «Нейтральная» — только цвет в интерфейсе. |
| Единица длительности | «раунд», «минута». Пусто — эффект без срока (снимается вручную). |
| Повторное наложение | «Обновляет длительность» / «Складывается» / «Запрещено». |
| Формула длительности | Например `10` или `Уровень`. |
| **Что изменяет эффект** (список бонусов) | Каждая строка: «Что изменяет» (Характеристика/Ресурс/Величина/Признак) + ссылка на объект + Формула. Например: Характеристика → Сила, Формула `-2` — это «−2 к Силе», как эффект «Истощение». Для чистых состояний вроде «Оглушён», у которых в D&D нет числовой формулы, а есть только текстовое правило — просто оставьте описание в тексте и не добавляйте строк бонуса, либо (лучше) заведите Признак с именем состояния, чтобы формулы правил могли его проверять. |

### Слоты экипировки

| Поле | Что писать |
|---|---|
| Допускает несколько предметов | Да только для колец и подобного. |
| Максимум предметов | Обычно 1, для колец — 2. |
| Порядок отображения | Любое число, определяет порядок в интерфейсе. |

Создавайте ДО предметов и оружия — иначе не на что будет сослаться.

### Категории предметов

| Поле | Что писать |
|---|---|
| Вышестоящая категория | Ссылка на другую категорию для дерева («Броня» внутри «Снаряжения»). Пусто — категория верхнего уровня. |

### Предметы (доспехи, снаряжение, зелья...)

| Поле | Что писать |
|---|---|
| Категория | Ссылка на категорию предметов. |
| Тип предмета | Свободный текст: «Броня», «Зелье», «Инструмент». |
| Редкость | «Обычный», «Необычный», «Редкий»... |
| Вес, Стоимость, Валюта | Числа + «зм»/«см»/«мм» и т. п. |
| Складывается в стопку | Да для стрел/зелий/еды. |
| Слот экипировки | Ссылка, если предмет надевается. |
| Формула зарядов | Для предметов с зарядами (жезлы). |
| Вмещает другие предметы | Да для рюкзаков/сумок. |
| Использование расходует | «Ничего» / «Заряд» / «Единицу предмета». |
| **Действия при использовании** | Список: Ресурс + Формула (например, для зелья лечения: Ресурс = Здоровье, Формула = `2к4 + 2`). |
| Требования | Например `сила >= 13`. |
| **Бонусы экипировки** | Список: Что изменяет + ссылка на объект + Формула + Условие. Для доспеха с «Класс доспеха 14 + модификатор Ловкости (максимум 2)» проще всего описать это текстом в Описании (как сделано в поставленном контенте), а не пытаться выразить формулой — числовые бонусы предмета лучше подходят для простых модификаторов вроде «+1 к Силе» у пояса великанской силы. |

### Оружие

Отдельный раздел в интерфейсе, но технически это тот же «Предмет» — просто
с дополнительными боевыми полями.

| Поле | Что писать |
|---|---|
| Тип оружия | «Одноручное», «Двуручное», «Метательное». |
| Категория | «Простое», «Воинское», «Ближнее», «Дальнобойное» — как удобно вашей системе. |
| Тип урона | «Рубящий», «Колющий», «Огонь». |
| Свойства | Через запятую: «лёгкое, фехтовальное, метательное» — каждое свойство становится признаком, который могут проверять правила. |
| Порог критического удара | 20 обычно (натуральная двадцатка). Пусто — крит. попаданий нет. |
| Характеристика масштабирования | Ссылка: Сила для ближнего оружия, Ловкость для дальнобойного/лёгкого. |
| Навык владения | Ссылка на навык-владение (см. совет в разделе «Навыки»). |
| Кость попадания | `1к20`. |
| Бонус попадания | `характеристика + владение * бонус_мастерства`. |
| Формула урона | `1к8 + характеристика` (кость оружия + модификатор). |
| Формула критического урона | `урон * 2` — здесь `урон` это уже вычисленный обычный урон. |
| Слот экипировки | Обычно «Основная рука». |

### Виды отдыха

| Поле | Что писать |
|---|---|
| Длительность + Единица | `1` час для короткого, `8` часов для длительного (или как в вашей системе). |
| Требования | Обычно пусто. |
| **Что восстанавливает отдых** | Список: Ресурс (пусто = «все ресурсы») + Способ («До максимума» / «По формуле») + Формула, если по формуле. Для длительного отдыха D&D: одна строка с пустым Ресурсом и способом «До максимума» восстанавливает всё разом. |

## 4. Формулы: что можно писать

Все формулы в приложении используют один и тот же движок, полностью
кириллический.

### Кубики

`1к20`, `2к6`, `8к6` — количество и грани через `к` (также работают `d`, `д`,
заглавные варианты). `к6` без числа перед буквой равнозначно `1к6`.

### Обращение к другим объектам

Внутри формулы название характеристики/навыка/ресурса пишется его
**внутренним именем** (то самое автополе «Внутреннее имя», обычно совпадает
с названием в нижнем регистре): `сила`, `ловкость`, `здоровье`. Регистр не
важен.

### Специальные переменные (доступны не везде, а только в соответствующем контексте)

| Имя | Где доступна | Что означает |
|---|---|---|
| `уровень` | везде, где есть персонаж | текущий уровень персонажа |
| `значение` | формула модификатора характеристики | собственное базовое значение характеристики |
| `владение` | формула навыка | уровень владения навыком (0/1/2...) |
| `характеристика` | формула навыка, оружия | модификатор связанной характеристики |
| `навык` | формулы оружия | значение связанного навыка |
| `урон` | формула критического урона | уже вычисленный обычный урон |
| `бросок` | правила боя | выпавшее значение кости |
| `попадание` | правила боя | итог броска попадания |

### Встроенные функции (все 13, других не изобретайте — движок их не знает)

| Функция | Что делает | Пример |
|---|---|---|
| `Минимум(...)` | наименьшее из значений | `Минимум(20, урон)` |
| `Максимум(...)` | наибольшее из значений | `Максимум(1, значение)` |
| `Сумма(...)` | сумма значений | |
| `Среднее(...)` | среднее арифметическое | |
| `Количество(...)` | количество переданных значений | |
| `Округлить(x, [знаков])` | округление к ближайшему | `Округлить(3.5)` = 4 |
| `ОкруглитьВниз(x)` | округление вниз | `ОкруглитьВниз((значение - 10) / 2)` — стандартный модификатор D&D |
| `ОкруглитьВверх(x)` | округление вверх | |
| `Модуль(x)` | абсолютное значение | |
| `Ограничить(x, мин, макс)` | зажимает значение в диапазон | `Ограничить(значение, 0, 20)` |
| `Если(условие, тогда, [иначе])` | условный выбор | `Если(уровень >= 5, 2, 1)` |
| `Кубик(количество, грани)` | бросок кубиков функцией, а не записью `2к6` | равнозначно `Кубик(2;6)` и `2к6` |
| `Случайное(мин, макс)` | случайное целое число в диапазоне включительно | |

Обычные операторы работают как в математике: `+ - * / ( )`, а также
сравнения `>= <= == != > <`.

**Важное ограничение:** логических «И»/«ИЛИ» в движке нет. Если требование
состоит из нескольких условий, либо используйте одно составное сравнение,
либо (для сложных случаев) вложенный `Если(...)`. На практике у 95% требований
одно сравнение: `сила >= 15`, `уровень >= 4`.

### Примеры формул, взятых из уже установленной у вас D&D 5e

- Модификатор характеристики: `ОкруглитьВниз((значение - 10) / 2)`
- Бонус мастерства (скрытая характеристика): `2 + ОкруглитьВниз((уровень - 1) / 4)`
- Навык: `характеристика + владение * бонус_мастерства`
- Здоровье класса: `1к10 + телосложение`
- Атака оружием: `характеристика + владение * бонус_мастерства`
- Урон оружием: `1к8 + характеристика`
- Критический урон: `урон * 2`

## 5. Требования (кто может выбрать объект)

Поле «Требования» есть у рас, происхождений, классов, подклассов, навыков,
черт, способностей, заклинаний, предметов, оружия, видов отдыха. Это то же
самое выражение формулы, но результат читается как истина/ложь.

Примеры:
- `сила >= 15` — раса/черта требует силу не меньше 15.
- `уровень >= 4` — черта доступна с 4 уровня.
- `ловкость >= 13` — лёгкая броня без штрафа (условно).

Если персонаж не подходит под требование — вариант остаётся в списке, но
помечается недоступным с пояснением («Требование не выполнено: сила >= 15»),
а не пропадает молча.

## 6. Что извлекать из книги — практические советы

Из личного опыта переноса «Книги игрока D&D 5e» (352 заклинания, 14 рас, 12
классов, 151 предмет, 37 видов оружия, 15 состояний):

- **Не сокращайте описания.** Копируйте текст правила целиком в поле
  «Описание» — это единственное место, где игрок его увидит внутри
  приложения. Экономия на объёме описания не даёт никакой пользы.
- **Заполняйте формулы только там, где они реально нужны.** Многие
  заклинания (иллюзии, вызовы, коммуникация) не имеют числового эффекта —
  оставляйте «Формулу результата» пустой, весь эффект описан текстом.
- **Не пытайтесь оцифровать всё до последней мелочи.** Сложные, ситуативные
  эффекты (например, полная механика заклинания «Стена силы» с десятком
  особых случаев) проще и надёжнее описать текстом в «Описании», чем
  городить формулу, которая всё равно не покроет все нюансы. Формулы нужны
  там, где есть чёткое число: урон, лечение, бонус, длительность.
  Механически сложные "рельсы" (что именно происходит по шагам) остаются на
  усмотрение игрока/мастера, читающих текст.
- **Состояния (условия)** вроде «Оглушён», «Отравлен» — заводите как
  Эффекты без формул бонусов (или с Признаком без числа), полный текст
  правила — в Описание. Их накладывают вручную через панель эффектов
  персонажа, движок не обязан знать, что именно означает «Оглушён» —
  это знает игрок, читающий описание.
- **Оружие и предметы** — единственное место, где стоит не полениться и
  прописать формулы полностью (урон, попадание, вес, стоимость): именно они
  считаются автоматически при броске атаки, и именно ради этого чаще всего
  затевается перенос книги правил.
- **Проверяйте по ходу дела.** Не обязательно вносить всю книгу за один
  присест. Экспортируйте расширение и проверяйте мастер создания персонажа
  после каждого крупного раздела (например, после всех рас) — так проще
  найти забытую «Игровую систему» на объекте, чем искать её среди трёхсот
  готовых записей в конце.

## 7. Экспорт и проверка

1. **Расширения → Выгрузить.**
2. Источник: выбираете вашу игровую систему из списка (система показывается
   как источник наравне с уже установленными расширениями — не перепутайте).
3. Название расширения, Версия, Автор, Описание, Лицензия — заполняете как
   считаете нужным, они попадут в манифест и будут видны при установке.
4. Жмёте «Выгрузить», выбираете, куда сохранить `.rpgpack`.
5. **Проверка перед тем, как делиться файлом:** самый надёжный способ — тот
   же, что использовался для книги игрока: создать персонажа в мастере и
   убедиться, что раса/класс/заклинания появились в списках выбора. Если у
   вас установлена только одна игровая система — она выберется в мастере
   автоматически; если несколько — не забудьте выбрать нужную на первом шаге
   «Игровая система».
6. Готовый `.rpgpack`-файл можно переслать кому угодно — он ставится через
   «Расширения → Установить» одной кнопкой, точно так же, как книга игрока,
   которую вы уже используете.

## 8. Короткий чек-лист перед выгрузкой

- [ ] У ВСЕХ созданных объектов заполнено поле «Игровая система».
- [ ] Слоты экипировки созданы раньше предметов/оружия, которые на них
      ссылаются.
- [ ] Подклассы ссылаются на существующий класс.
- [ ] Формулы урона/попадания/здоровья проверены хотя бы на одном примере
      (создайте тестового персонажа и посмотрите на вычисленные значения).
- [ ] Описания скопированы полностью, а не сокращены.
- [ ] Экспорт сделан из «Игровой системы», а не по ошибке из старого
      контент-пака.
